# LED Animator

`led_animator.py` turns any video into a 16×16 RGB LED animation. Each LED has
three 8-bit intensity channels (`R`, `G`, and `B`, each from 0 to 255), so the
result represents all 16,777,216 possible RGB colors.

The companion `led_animator_48.py` uses the same conversion, export, preview,
and playback pipeline for a 48×48 RGB grid.

## Quick start

From the project directory, create a Python environment and install the
dependencies:

```bash
cd ~/dev/led_animator
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Copy a video into `video_clips/`, then generate the animation:

```bash
python3 led_animator.py video_clips/my_video.mp4 -o output/my_animation
```

For the 48×48 version, the recommended command runs inside a memory-limited
container:

```bash
./run_48_container.sh video_clips/my_video.mp4 -o output/my_video_48
```

On first use, the runner builds a dependency image; later runs reuse it while
loading the current scripts from the mounted project. It starts conversion with
a 1 GiB memory limit, no additional swap, two CPUs, and no network. If
conversion exceeds the memory limit, Docker kills the containerized process
instead of letting it consume unbounded host RAM. Input and output paths must
be relative to this project because only the project directory is mounted into
the container.

Change the limits when needed without editing the script:

```bash
LED_ANIMATOR_MEMORY_LIMIT=2g LED_ANIMATOR_CPU_LIMIT=4 \
  ./run_48_container.sh video_clips/my_video.mp4 -o output/my_video_48
```

Without `-o`, the 48×48 entry point writes `my_video_48x48.*` beside the
input so it does not overwrite output generated by the 16×16 script. Its
default simulator preview gives every logical LED an 8×8 circular face with
2-pixel spacing, colored bloom, and a bright core, producing a 482×482 H.264
MP4.

The command creates the following files in `output/`:

- `my_animation.preview.mp4`: H.264 visual preview with bright LED cores and
  soft, camera-like color halos;
- `my_animation.ledmap.json`: portable RGB intensity map;
- `my_animation.ledanim.npz`: compact, lossless board and playback data.

Play the generated animation in the desktop viewer with:

```bash
python3 led_animator.py --play output/my_animation.ledanim.npz
```

Replace `my_video.mp4` with the actual name of the video you placed in
`video_clips/`.

For every frame, the generator now:

1. center-crops the video to a 1:1 square;
2. asks FFmpeg to area-average the crop directly to the target grid before it
   enters Python;
3. immediately writes the RGB grid to a disk-backed temporary frame store and
   releases the decoded frame.

This is area/color merging, not nearest-neighbor pixel picking, so small bright
details contribute to the final LED intensity instead of disappearing. NPZ
compression then reads a bounded number of frames at a time, JSON is written
one row at a time, and MP4 frames are streamed individually through FFmpeg.
The whole animation is never retained in RAM during conversion.
Requested outputs are staged beside the destination and moved into place only
after every export finishes, preventing an OOM or normal export error from
mixing new and stale output formats.

## Requirements

- Python 3.10+
- FFmpeg (`ffmpeg` and `ffprobe` on `PATH`)
- Python packages in `requirements.txt`
- Docker, when using the recommended isolated 48×48 runner

```bash
python3 -m pip install -r requirements.txt
```

## Generate an animation

```bash
python3 led_animator.py input.mp4 -o output/my_animation
```

This creates:

- `my_animation.ledanim.npz`: compact, lossless NumPy data for Python playback
  and future board drivers;
- `my_animation.ledmap.json`: portable LED intensity maps;
- `my_animation.preview.mp4`: an H.264 visual preview with round LEDs.

The JSON stores frames as `frames[frame][row][column][channel]`. Coordinates
start at the top-left, pixels are row-major, and channels are ordered RGB. Each
channel is an integer from 0 through 255. `frame_duration_us` gives board-driver
timing without requiring floating-point math.

Useful options:

```bash
# Convert and immediately show a live desktop preview
python3 led_animator.py input.mp4 --preview-after

# Skip the larger portable outputs when only compact board data is wanted
python3 led_animator.py input.mp4 --no-json --no-preview

# Change preview appearance
python3 led_animator.py input.mp4 --led-size 28 --gap 3

# Change only the exported MP4 frame rate
python3 led_animator.py input.mp4 --preview-fps 10

# Use smaller NPZ compression batches when memory is especially constrained
python3 led_animator_48.py input.mp4 --batch-size 4

# Regenerate only the MP4 preview from exact frames already stored in an NPZ
./run_48_container.sh --preview-from output/my_animation.ledanim.npz \
  -o output/my_animation
```

The default MP4 preview is H.264 encoded. The 16×16 converter renders a
256×256 preview, while the 48×48 converter renders a 482×482 simulator view
so circles, spacing, highlights, and bloom remain visible. It preserves the source
frame rate and every source frame up to 60 FPS; higher-rate inputs are sampled
down to 60 FPS. Its
inter-frame compression is substantially smaller than GIF for animation.
Reducing the MP4 frame rate keeps long previews lightweight without removing
frames from the NPZ or JSON animation data. Its
brightness lift and glow affect only the visual preview and desktop player;
the RGB values saved in `.ledanim.npz` and `.ledmap.json` remain unchanged.
Use `--preview-fps` to change only the exported MP4 frame rate. The former
`--gif-fps` spelling remains a compatibility alias. Use `--led-size`
and `--gap` to generate a larger or smaller preview. A larger gap gives each
LED halo more room to remain individually visible.

## Memory and disk usage

The streaming implementation keeps memory bounded. A 48×48 animation's
temporary raw store uses exactly 6,912 bytes per frame (about 203 KiB per
second at 30 FPS). NPZ compression, JSON, and the MP4
also require disk space while that temporary store exists. For long videos,
consider disabling the much larger text and preview exports:

```bash
./run_48_container.sh video_clips/long_video.mp4 \
  -o output/long_video_48 --no-json --no-preview --batch-size 4
```

The temporary frame store is removed after a successful conversion or a normal
error. Use `--batch-size` to control how many frames NPZ compression reads at
once; the default is 16 (108 KiB of raw 48×48 frame data).

## Play a generated animation

```bash
python3 led_animator.py --play output/my_animation.ledanim.npz
```

Desktop playback uses Tkinter and loops at the source video's average frame
rate. The MP4 can be opened in ordinary video players when a desktop/Tk display
is unavailable.

Loading the lossless frames for a future board driver is straightforward:

```python
import numpy as np

with np.load("output/my_animation.ledanim.npz") as animation:
    frames = animation["frames"]  # uint8 shape: (frame_count, 16, 16, 3)
    fps = float(animation["fps"])

for frame in frames:
    # send_to_board(frame.reshape(256, 3))
    pass
```
